# Provider-Routing, Policy & Limits

Ausgelagert aus CLAUDE.md am 2026-09-21; laedt automatisch bei Zugriff auf dispatcher.py, policy.py, profiles.py, limits.py, tests/conftest.py.

- **`dispatcher.py`** — Provider selection (Claude → Codex fallback; **Gemini left `_PRIORITY` 2026-08-15** — IneligibleTierError + data protection. The provider stays registered, so `#gemini*` tags and `get_provider_by_name` still resolve; nothing routes there by default), cooldowns, model-alias routing; `_NO_FALLBACK_PROVIDERS = {"vibe", "opencode"}` (renamed 2026-09-04 from `_REVIEWER_ONLY` when opencode joined) guard so an unregistered vibe/opencode tag parks the task instead of degrading to another provider — two different reasons, one mechanism: vibe is blast radius (non-writing reviewer → writing executor), opencode is tag intent (the tag itself asks to avoid Claude quota, or for customer code the only ZDR path — a silent fallback would defeat it). **Policy gate:** `get_provider_by_name()` is the policy-BLIND registry lookup — tool code must use `get_provider_for_tool(name, tool)` / `policy_provider_lookup(tool)`, and `forced_provider_policy_violation()` lets the orchestrator tell "policy said no" apart from "no capacity" (both surface as `select_provider() → None`, but only the latter is worth waiting for)
- **`policy.py`** — `PolicyEngine` singleton, AUTO/APPROVE/DENY classification, Telegram-blocking; P3 `ToolContract` API (`get_tool_contract(name)`) + `tool_contracts:` yaml section (per-tool budget/stop_conditions/reporting_path, doctor schema-validates)
- **`profiles.py`** — `#agent:<name>` YAML profiles (provider order, allowed roots, skill allow/deny, timeout, policy overrides); vault first, repo-local second. `_KNOWN_PROVIDERS` (fixed 2026-09-04) is derived from `dispatcher._TAG_MAP` instead of a hand-copied `{"claude","gemini","codex"}`, same reasoning as `PROVIDER_TAG_RE` above: a profile naming `vibe`/`openrouter` used to be indistinguishable from a typo and got silently replaced by the default list. `_DEFAULT_PROVIDERS` stays `[claude, gemini, codex]` and is deliberately NOT derived — "known" and "default" are different questions, and defaulting every profile to pay-per-token providers it never asked for would be the opposite of the fix. A discarded name now logs a WARNING naming it instead of vanishing quietly. **The invariant `_DEFAULT_PROVIDERS ⊆ _KNOWN_PROVIDERS` is now load-bearing and tested** (`tests/test_provider_list_derivation.py::test_known_providers_drift_guard`, same-day follow-up): `_build_profile_config()` has two separate paths that fall back to the default — `providers:` omitted, or every named entry discarded — and only the second one used to run the default through the `_KNOWN_PROVIDERS` filter; the first appended it raw. While the invariant holds the two paths agree by coincidence, but a future cleanup that retires a provider from `_TAG_MAP` (e.g. `gemini`) without also touching `_DEFAULT_PROVIDERS` would make them disagree silently — the fallback line now filters both the same way, and the test fails loudly instead of the two default lists quietly drifting apart
- **`limits.py`** — `cclimits` wrapper, OAuth refresh, 3-tier 429 fallback, polling 10min idle / 5min active (idle matches cclimits `--cache-ttl=600`); Phase-0 calibration hook in `_bg_refresh_loop`. `AllLimits.opencode` ist NICHT aus `cclimits` (kein OAuth-Kontingent) — `_apply_opencode_budget_override()` befüllt es live über `openrouter_budget.fetch_budget()`, **fail-closed** (Gegenteil von Claude/Codex: unbekanntes Budget → `available=False`, weil ein opencode-Lauf echtes Geld kostet, ein stales Claude-Kontingent nicht). Schwelle `config.OPENCODE_MIN_REMAINING_USD` (0.25, strikt `>`); Reset-Zeitpunkt aus der API-Cadence (`daily`/`weekly`/`monthly`) ist eine benannte ANNAHME (UTC-Mitternacht, keine echte Zeitstempel-Angabe) und beeinflusst nur `earliest_reset_sec()`, nie `available`. Drei `AllLimits`-Aggregatmethoden zählen die Provider-Felder von Hand auf — Drift-Guard-Test iteriert `dataclasses.fields(AllLimits)`. **`all_provider_names()` / `display_provider_names()` (2026-09-09)** sind die abgeleitete Gegenrichtung: `all_provider_names()` ist `fields(AllLimits)` (welche Provider **existieren**), `display_provider_names()` dasselbe gefiltert durch ein lazy importiertes `dispatcher.policy_allows_provider(name, None)` (welche davon **erreichbar** sind), gemessen am Live-Vault `('claude','codex','opencode')`. Gemini fällt heraus, weil seine Stilllegung vom 2026-08-15 es aus `tool_providers` genommen hat — die Anzeige folgt dieser Entscheidung, statt sie in einer zweiten Liste zu wiederholen. **Welche der beiden, entscheidet Anzeige gegen Aufzeichnung** (korrigiert im Quality-Pass desselben Tages, erste Fassung filterte beide): die drei menschenlesbaren Stellen (Heartbeat-Text, `/status`, `/limits`) nehmen `display_provider_names()`, `heartbeat._append_capacity_log()` nimmt `all_provider_names()`. Der Capacity-Log ist ein **Datenrekorder**, kein Text — `analytics._parse_capacity_log()` speist daraus das Current-Limits-Panel und die historische Reihe des Dashboards. Ein Policy-Filter dort räumt keine Meldung auf, sondern **beendet die Zeitreihe eines Providers**, und zwar auch für einen, der weiterläuft: bei `default: [claude]` plus `dev-loop: [claude, codex]` führt Codex weiter dev-loop-Tasks aus, während der `default:`-Lookup ihn wegfiltert und ab dem nächsten Heartbeat keine Codex-Zeile mehr geschrieben wird. Aufzeichnen ist billig, eine Lücke in der Reihe ist nicht rekonstruierbar. **Fail-open** (jede Störung beim Policy-Lookup zeigt alle Felder — eine verschwundene policy.yaml erzeugt Rauschen, keine Blindheit; fail-closed würde die Statusmeldung genau dann leeren, wenn ohnehin schon etwas kaputt ist) und **nie leer**. Bekannte Grenze: gefragt wird der `default:`-Eintrag, ein nur für ein einzelnes Tool erlaubter Provider wäre in der Anzeige damit unsichtbar (im Log nicht — der ist ungefiltert). **Registrierung wird ZUERST geprüft, vor jeder Budget-Abfrage** (2026-09-04, interner Quality-Pass): das Budget hängt am OpenRouter-Key und beantwortet deshalb auch auf einer Maschine ohne opencode-Binary „ist Geld da" mit ja — `available=True` wanderte damit in Aggregate, die etwas anderes bedeuten. Gemessen mit claude/gemini/codex auf `False`: `any_available()` kippt von False auf True (`run_watch` schläft 30 s statt bis zu `SLEEP_POLL_INTERVAL*10` und startet jede Runde einen echten `cclimits`-Subprozess), `_compute_next_poll_sec` geht von 30 auf 300 s, und `earliest_reset_sec()` nimmt ein `min()` über opencodes **angenommene** UTC-Mitternacht, kann also Retry-Zeitpunkt und `notify_providers_exhausted`-Meldung für einen Provider bestimmen, auf den nichts routen kann. `_opencode_budget_snapshot()` liefert deshalb ohne registrierten Provider sofort `available=False, error="not_registered"` — und spart nebenbei den HTTPS-Roundtrip bei jedem Refresh auf Maschinen ohne opencode. Der `dispatcher`-Import ist bewusst lazy (dispatcher importiert limits auf Modulebene → Zyklus).
- **Provider ceiling for unattended tasks (2026-08-15)** — `policy.yaml` `tool_providers:` lists **every** tool in `tools/registry.py` explicitly with `[claude, codex]` (`review-loop`/`test-loop`: `[claude]`), plus the same `default:`. Reason: `dispatcher._limits_ok()` returns `True` unconditionally for `openrouter` and `vibe`, so those two have no capacity gate and no cost ceiling. opencode is **not** part of this reasoning — it IS capped (own OpenRouter key, `limit: 5`/`limit_reset: "daily"`, polled live, see `limits.py`) — but it inherits the same gate as a side effect, and the shape of that is worth stating exactly, because the first version of this paragraph got it wrong. `default:` is not only the fallback for an unlisted **tool** — it is also the entry a plain queue line without any `#tool:` gets. So while `default:` read `[claude, codex]`, opencode was barred on **every** route, not just the tool routes: a bare `#opencode` task ended terminal ❌ with `provider_not_allowed` (measured 2026-09-04 — `forced_provider_policy_violation("… #opencode")` → `('opencode', ['claude','codex'])`), which is the exact opposite of the tag activation Stufe 2 was built for, and `--lint-queue` says nothing about it because the linter checks CLI registration, not policy. `default:` therefore now reads `[claude, codex, opencode]`. That opens no fallback route — opencode is not in `dispatcher._PRIORITY`, so it still runs only on an explicit tag — and the eleven tool entries are unchanged, so opencode stays unreachable for every `#tool:` task; widening a specific tool's entry is still the deliberate way to open that up later. The price, named rather than discovered later: a **future** tool without its own entry now inherits opencode along with claude/codex. The ceiling holds on **all three** routes for openrouter/vibe, which it did not when it was introduced: (1) the fallback chain; (2) an explicit `#openrouter`/`#vibe` tag — the forced provider used to be prepended *after* the filter, making the filter a no-op for exactly the two providers it exists to bar. A barred tag is now a terminal, logged failure (`error_code="provider_not_allowed"`), never a silent reroute to another provider; (3) tool-internal lookups, which went through the policy-blind `get_provider_by_name`. Those now use `dispatcher.get_provider_for_tool(name, tool)` / `policy_provider_lookup(tool)` — second-opinion (`review_loop`), pass 2 (`critical_review`), and the cross-provider allocators in `brainstorm_phases`, `scientific_investigation_phases`, `scientific_investigation_phase7`, `scientific_investigation` phase 5b. The candidate tuples there are unchanged: a barred provider resolves to None and drops out, so diversity degrades instead of breaking. **Alle sieben rohen Call-Sites sind umgestellt** (Rest-Lücke geschlossen 2026-08-15): die letzten beiden waren `tools/brainstorm.py` und `tools/scientific_investigation_phase2.py` — nicht die Allokation, sondern der Schritt, der eine Allokation in eine Provider-Instanz **auflöst**. Das ist kein doppeltes Gate: die Allokationsliste kann aus einem persistierten State-File oder aus dem degradierten Fallback-Pfad stammen und damit die Policy überleben, die sie erzeugt hat — ein Name, der beim Schreiben zulässig war, wird jetzt vor dem Prompt erneut geprüft. Beide Stellen benutzen `policy_provider_lookup(_TOOL_NAME)`; ein gesperrter Name löst zu None auf und degradiert auf den Primary. **Bewusst roh bleibt `tools/critical_review.py:411-420`:** es fragt erst `policy_allows_provider()` und dann `get_provider_by_name()`, weil „Policy sagt nein" und „Provider unbekannt" unterschiedliche Log-Zeilen brauchen — genau der Fall, den der Docstring von `get_provider_for_tool()` als Ausnahme nennt. **Measured degradation under the current policy:** brainstorm round-robin spans claude+codex only; the scientific-investigation Methodiker persona falls back to the primary (one cross-provider left, which the DA takes); `#second_opinion:codex|vibe|or_*` is inert for `review-loop` (`[claude]`) — only `#second_opinion:claude_*` still resolves there
  - **The ceiling also has to survive the policy file going missing (2026-08-15, external review).** `policy.yaml` lives in a OneDrive-synced folder, and `PolicyEngine` reports a missing, unreadable or unparseable file as "no restriction configured" — indistinguishable from a deliberately empty policy. `policy_allows_provider()` answered that with a blanket `True`, so a sync collision re-opened `openrouter` and `vibe` for an unattended 03:00 run, i.e. the exact two providers with no cost ceiling. The rule is now **asymmetric**, in `dispatcher._allows()`: fail-**open** for the capped providers (a lost policy must not take the orchestrator offline), fail-**closed** for `dispatcher._UNCAPPED_PROVIDERS` — one frozenset that `_limits_ok()` also reads, so "no capacity gate" and "barred by default" cannot drift apart. An explicit allow-list naming them (policy.yaml, profile, or a `#tool_providers:` queue tag) is a deliberate authorisation and still works. **`_UNCAPPED_PROVIDERS` stays `{"openrouter", "vibe"}` — opencode is deliberately NOT added (2026-09-04).** It IS pay-per-token, but unlike the other two its cap is pollable: a dedicated OpenRouter key behind it carries a real `limit`/`limit_remaining` (`GET /api/v1/key`, applied fail-closed by `limits._apply_opencode_budget_override()`), so `_limits_ok()` reaches the same `getattr(limits, name).available` path every capped provider uses, and `_allows()` stays fail-**open** for it on a missing/unreadable policy.yaml, exactly like claude/codex — a lost config file bars an already-capped provider from nothing extra. **Second hardening on the same file:** nothing validated the section's *shape*, so `dev-loop: claude` (scalar, no brackets) became `['c','l','a','u','d','e']` and a mapping became its key list — both read downstream as well-formed allow-lists that match nothing. `policy._coerce_provider_list()` now normalises the entry, a non-mapping `tool_providers:` is ignored with a warning, and `dispatcher._sanitize_allowed()` repeats the coercion as defence in depth (a junk entry degrades to "no restriction" instead of raising TypeError out of the run loop)
  - ✅ **`select_provider()` is fail-closed on both branches (profile branch 2026-09-04, tag/forced branch 2026-09-17).** `_selection_order()`'s profile branch clears `_allows()` per candidate (test `tests/test_dispatcher_routing.py::test_profile_provider_order_fails_closed_on_uncapped_provider`). The forced branch used to test `if forced and allowed and forced.name not in allowed` — truthiness only — so with `allowed is None` a bare `#openrouter`/`#vibe` tag was prepended and started (`_limits_ok()` is unconditionally `True` for the uncapped set). Now both `_selection_order()` and `forced_provider_policy_violation()` ask `_allows(forced.name, allowed)` — the same function, not a copy — and the violation returns `_effective_allowed(allowed)`, so the message never prints an empty list. The existing terminal path in `orchestrator.run_once()` (tool and single-shot) then applies unchanged: `print` + `append_log` + `notify_error` + ❌ finalisation, `error_code="provider_not_allowed"`. opencode, claude, codex and gemini stay fail-open. **Scope of the behaviour change, named:** `PolicyEngine` cannot tell a missing file from one without a `tool_providers:` section, so such an installation now also rejects bare uncapped tags (the live vault policy lists `default:` explicitly — unchanged there). Explicit authorisation still works (`tool_providers:` entry, profile, `#tool_providers:` tag); the four routing tests that route to openrouter/vibe now carry that tag. `#parallel` subtasks inherit the gate via `select_provider(force_name=…)` but have no dedicated violation message — they just fail. Tests: the missing-policy block in `tests/test_dispatcher_routing.py`, `tests/test_orchestrator_tool_tasks.py::test_run_once_bare_vibe_tag_under_missing_policy_is_terminal_provider_not_allowed` (nothing in the policy path mocked), and `tests/test_queue_linter_policy.py::test_bare_uncapped_tag_under_a_missing_policy_is_reported_as_barred`. - **Tool Contracts (P3)** — `tool_contracts:` section in `policy.yaml`; `PolicyEngine.get_tool_contract(name)` returns dataclass with `max_iterations`/`max_runtime_sec`/`stop_conditions`/`reporting_path`; tools may fall back to `config.TOOL_*_*` constants for fields the contract omits (staged migration)
- **HTTP 429 resilience** — 3-tier fallback (claude-monitor JSONL → snapshot cache → optimistic), 5-min polling backoff
- **3-tier token estimation** — actual JSON → text-char estimate → duration heuristic
- **Ein Test, der über einen bedingt registrierten Provider urteilt, nimmt die passende Fixture aus `tests/conftest.py`: `with_opencode`/`without_opencode` oder `with_vibe`/`without_vibe`** (beide Paare dorthin gezogen 2026-09-09, vorher lokal in `tests/test_dispatcher_routing.py`, das vibe-Paar zusätzlich in `tests/test_provider_list_derivation.py` dupliziert). Ohne sie hängt das Ergebnis an der Maschine, in zwei Ausprägungen: `dispatcher.resolve_forced_provider()` liefert für einen nicht registrierten Namen `None`, also meldet `forced_provider_policy_violation()` nichts, und ein Test, der genau diesen Befund erwartet, wird grün ohne zu prüfen; und `_selection_order("… #vibe", …)` liefert `['vibe','claude','codex']` nur mit registriertem vibe, sonst `['claude','codex']` — gemessen 2026-09-09, der Test, der die offene Lücke im Forced-Zweig festnagelt, war so nur auf dieser Box grün. Dieselbe Falle traf zuerst die beiden Policy-Linter-Tests. Faustregel: **wer den Provider im Namen trägt, nimmt die Fixture** — auch wenn es gerade grün ist. Nicht betroffen sind Prüfungen, die reine Policy- oder Alias-Fragen stellen (`policy_allows_provider()`, `review_loop.second_opinion_target()`), die kennen die Registry nicht
